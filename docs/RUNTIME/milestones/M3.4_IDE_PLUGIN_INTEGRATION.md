# M3.4 — IDE Plugin Integration

## Objective

Ensure that **IDE actions of interest are routed through the governed runtime path**. No IDE action of interest may bypass runtime governance.

Execution chain:

```
IDE action → plugin bridge/client → runtime request → LoopController → Plan-Gate 
→ sandbox (only if allowed) → governed result returned to plugin → IDE UX reflects runtime outcome truthfully
```

## Architectural Principles

The plugin is a **client**, not a governor.

### The plugin MUST NOT:
- Make governance decisions itself
- Reinterpret posture semantics
- Execute protected actions locally as fallback
- Silently bypass runtime when runtime is unavailable
- Collapse distinct outcomes into generic "failed" or "success" states

### The plugin's job is:
- Intercept or initiate actions
- Package requests
- Call runtime
- Display governed outcomes
- Avoid bypasses

The **runtime remains the source of truth**.

### Runtime Outcomes

The plugin surfaces **7 distinct outcomes** — no collapsing:

| Outcome | Meaning | UX Treatment |
|---------|---------|--------------|
| `REFUSED` | Runtime governance denied the action | Error notification |
| `DEFERRED` | Action deferred pending approval | Warning notification |
| `BOUNDED_ALLOW` | Bounded-safe allowance, no sandbox execution (MVP) | Warning notification |
| `BLOCKED` | Execution path reached but blocked by policy | Error notification |
| `EXECUTED` | Action executed through governed runtime path | Info notification |
| `RUNTIME_UNAVAILABLE` | Runtime service unreachable, fail-closed | Error notification |
| `UNKNOWN` | Unexpected/invalid runtime response | Warning notification |

## Intercepted Actions

### 1. VCS Commit Interception

**Flow:**
```
Developer initiates commit
→ MotadataCheckinHandler.beforeCheckin()
→ RuntimeBridge.evaluateCommit()
→ POST /v0/plan
→ Runtime decision
→ Plugin shows notification
→ (Shadow mode) Commit proceeds with decision logged
→ (Enforcing mode) Commit blocked if not EXECUTED
```

**Modes:**
- **Shadow mode**: Logs decisions but allows commits (default)
- **Enforcing mode**: Blocks commits unless runtime approves

### 2. Ask / Plan Request

**Flow:**
```
Tools → "Ask Motadata AI"
→ User enters question
→ RuntimeBridge.askPlan()
→ POST /v0/ask
→ ContextEngine + PlanOnlyPlanner
→ PLAN ONLY response with context bundle
```

**Invariants:**
- `governance_posture == "PLAN_ONLY"`
- `execution == false`
- No sandbox invocation

### 3. Submit to Runtime (Explicit Execution)

**Flow:**
```
Tools → "Submit to Runtime"
→ User enters command
→ RuntimeBridge.requestExecution()
→ POST /v0/execute
→ Plan-Gate decision (PlanGateService.evaluate)
→ Ledger Plan-Gate decision (when ledger_path provided)
→ If safe_execute: sandbox runs → ledger sandbox outcome
→ Response includes decision_ledger_row_id and (if executed) ledger_row_id
```

**Important:** This action demonstrates the full plugin → runtime → Plan-Gate → sandbox path.

**Runtime behavior (M3.4 hardening):**
- **Plan-Gate decision ledgering:** When the request includes `ledger_path` (or `MOTADATA_EXECUTE_LEDGER_PATH` is set), the /v0/execute path persists the Plan-Gate decision **before** sandbox execution or early return. All four postures (refuse, defer, bounded_allow, safe_execute) are written as plangate_* event types. Decision truth is persisted separately from execution truth.
- **Production governance:** Governance decisions come from `PlanGateService.evaluate(request)` only. No command-string keyword heuristics are used for production posture; only explicit request fields `plan_gate_refuse`, `plan_gate_defer`, `plan_gate_bounded_allow` (test/demo control) may override.
- **Command parsing:** Command string is parsed with `shlex.split()` for correct handling of quoted arguments; invalid or empty command is rejected (blocked). Execution remains `shell=False` downstream.

## Request/Response Contract

### RuntimeRequest (Plugin → Runtime)

```kotlin
data class RuntimeRequest(
    val requestId: String,           // Unique tracing ID
    val actionType: RuntimeActionType, // VCS_COMMIT, ASK_PLAN, EXECUTE, VALIDATE
    val taskId: String?,             // Multi-step workflow ID
    val repoRoot: String,            // Repository root path
    val revision: String?,           // Git SHA
    val branch: String?,             // Git branch
    val payload: String?,            // Command or query text
    val planHash: String?,           // Prior plan hash
    val ideContext: IdeContext,      // IDE metadata
    val timestampUtc: String,        // ISO-8601 UTC
    val clientPolicy: ClientPolicy   // Fail-closed, mode
)
```

### RuntimeResponse (Runtime → Plugin)

```kotlin
data class RuntimeResponse(
    val outcome: RuntimeOutcome,     // One of 7 distinct outcomes
    val requestId: String?,          // Echoed back
    val ui: RuntimeUi?,              // Title, message, severity
    val reason: String?,             // Decision reason
    val wasExecuted: Boolean,        // Did sandbox run?
    val ledgerRowId: String?,        // Audit trail
    val planHash: String?,           // Plan hash
    val error: String?,              // Error if runtime call failed
    val metadata: Map<String, Any?>  // Additional data
)
```

## Failure Semantics

### No-Bypass Rules

| Scenario | Behavior |
|----------|----------|
| Runtime unavailable (shadow mode) | Warning notification, action proceeds, logged as `RUNTIME_UNAVAILABLE [SHADOW]` |
| Runtime unavailable (enforcing mode) | Error notification, action blocked, logged as `RUNTIME_UNAVAILABLE [NO_FALLBACK]` |
| Invalid response | Warning notification, action blocked in enforcing mode |
| Unknown posture | Mapped to `UNKNOWN`, warning notification |

### Fail-Closed Semantics

In **enforcing mode**:
- `EXECUTED` → action proceeds
- `BOUNDED_ALLOW` → action proceeds (MVP: planning-only safe)
- All other outcomes → action blocked

## Scope (MVP)

M3.4 covers:
- Commit interception (shadow/enforcing)
- Ask flow (PLAN ONLY)
- Explicit runtime execution action (/v0/execute)
- Fail-closed plugin/runtime bridge

Not in MVP scope: push interception, full IDE coverage, or full plugin E2E in running IDE sandbox.

## Out-of-Scope (MVP)

- **Push interception**: Only commit is intercepted in MVP
- **Full IDE coverage**: Only 3 actions (commit, ask, submit) are governed
- **Enforcing mode by default**: Shadow mode is default
- **Real sandbox execution for bounded_allow**: MVP has no bounded sandbox profile
- **IDE settings UI**: No settings panel for plugin configuration



