# M3.3 — Plan-Gate Integration

## Objective

Guarantee that **all execution paths flow through the governed Plan-Gate decision pipeline** before any sandbox execution can occur. No execution path may bypass Plan-Gate.

Execution chain:

```
request → Plan-Gate → runtime decision → LoopController transition → sandbox (if allowed) → ledger evidence
```

## Architecture

- **Plan-Gate** is the mandatory pre-sandbox gate. The LoopController calls `PlanGateService.evaluate(request)` before applying the `validated_to_sandbox` transition.
- **Postures**: `refuse` | `defer` | `bounded_allow` | `safe_execute`. Only `safe_execute` may proceed to sandbox.
- **Governance**: DES → reasoning only; CONF → bounded safe action; CODE → execution via sandbox only.

## Decision Model

- **PlanGateDecision**: `posture`, `authority_ok`, `boundary_detected`, `irreversible`, `reason`.
- **PlanGateService.evaluate(request)**: Returns PlanGateDecision. MVP implementation is deterministic and rule-based (no LLM). Request may include `request_id`, `plan_hash`, `command`, `plan_gate_defer`, `plan_gate_refuse`, `plan_gate_bounded_allow` for demo/control.

## Runtime Flow

1. Controller receives `validated_to_sandbox` with guard_inputs (command, working_dir, optional plan_gate_defer / plan_gate_refuse / plan_gate_bounded_allow).
2. If Plan-Gate not configured → refuse; persist refusal row; return `TransitionResult(valid=False)`.
3. Build request dict; call `PlanGateService.evaluate(request)` → decision.
4. Persist Plan-Gate decision to ledger (plangate_refused | plangate_deferred | plangate_bounded_allow | plangate_safe_execute).
5. If posture **refuse** → return REFUSED, persist sandbox_refused; sandbox does not run.
6. If posture **defer** → return `TransitionResult(valid=False, stop_reason="deferred")`; plangate_deferred persisted; sandbox does not run.
7. If posture **bounded_allow** → return `TransitionResult(valid=False, stop_reason="bounded_allow")`; plangate_bounded_allow persisted; sandbox does not run. (Distinct from defer; reserved for future CONF-phase bounded execution semantics.)
8. If posture **safe_execute** → call `_run_sandbox_and_persist`; sandbox runs; sandbox_executed (or refused on executor error) persisted.

## Failure Semantics

- **Plan-Gate not configured**: Treated as refuse; no sandbox; refusal row persisted when ledger_store present.
- **Persistence failure** (e.g. ledger append raises): Fail-closed; TransitionResult includes reason and ledger_row_id=None where applicable.
- **Deterministic behavior**: Same request → same decision; no LLM or non-deterministic calls in PlanGateService.

## Tests / Evidence

- **Unit**: `runtime/tests/test_plangate_integration.py` — PlanGateDecision, PlanGateService (curl refused, echo safe_execute, force_defer, force_refuse, force_bounded_allow); LoopController integration (refusal/defer/bounded_allow prevent sandbox; safe_execute allows; decision persists). bounded_allow tested as distinct from defer (stop_reason, event_type).
- **Demo**: `python3 -m runtime.sandbox.demo_governed_execution` — SAFE_EXECUTE → EXECUTED, REFUSE (curl), REFUSED (no gate), DEFER, BOUNDED_ALLOW; decision + outcome printed; 7 ledger rows including plangate_bounded_allow.
- **E2E**: `runtime/tests/test_sandbox_demo_e2e.py` — all five cases (executed, blocked/refused, refused, deferred, bounded_allow) through controller spine; summary contains bounded_allow outcome; ledger rows include plangate_bounded_allow.

## Out-of-Scope (MVP)

- LLM-based or adaptive Plan-Gate evaluation.
- Full authority/boundary integration (emulator M3.E0 has richer authority/boundary; M3.3 uses simple rule-based refuse/defer/bounded_allow/safe_execute).
- IDE plugin wiring to Plan-Gate (M3.4).
- **No dedicated bounded sandbox profile yet** — bounded_allow is a first-class Plan-Gate posture and is ledgered with `plangate_bounded_allow`, but it does **not** reach sandbox in MVP. Richer bounded execution (e.g. read-only inspection, test-only execution, limited command set) is explicitly future work.

## Future Follow-Up

`bounded_allow` may later map to a restricted sandbox profile (e.g. read-only inspection, test-only execution, limited command set). That is explicitly out of scope for this sprint; this milestone establishes the posture and runtime/ledger contract only.
