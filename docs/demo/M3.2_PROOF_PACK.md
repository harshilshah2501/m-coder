# M3.2 Proof Pack — Governed Execution Demo

Canonical evidence for the three runtime outcomes: **REFUSED**, **BLOCKED**, **EXECUTED**.

## How to run the demo

```bash
python3 -m runtime.sandbox.demo_governed_execution
```

Or run the E2E test harness:

```bash
python3 -m pytest runtime/tests/test_sandbox_demo_e2e.py -v
```

## Summary of cases

| Case       | Outcome   | Description                                      | Ledger event type   |
|-----------|-----------|--------------------------------------------------|---------------------|
| **REFUSED** | Refused   | Runtime denies before sandbox (e.g. no executor) | `sandbox_refused`   |
| **BLOCKED** | Blocked   | Policy disallows command; command does not run   | `sandbox_blocked`   |
| **EXECUTED**| Executed  | Allowed command runs; artifacts captured        | `sandbox_executed`  |

## Example evidence (from demo run)

### REFUSED

- **Reason**: Sandbox executor not configured for PROPOSAL_VALIDATED → SANDBOX_EXECUTED
- **Ledger row id**: `refused-demo-refused-<hash>`
- **Verification**: Sandbox is not launched; refusal row persisted in SQLite ledger

### BLOCKED

- **Command**: `curl http://example.com`
- **Blocked reason**: Command 'curl' not in allowed list
- **Ledger row id**: `blocked-demo-blocked-<hash>`
- **Verification**: Command does not execute; blocked row persisted

### EXECUTED

- **Command**: `echo hello`
- **Result**: success, exit_code 0, stdout_summary "hello\n"
- **Ledger row id**: `sbx-<deterministic-hash>`
- **Verification**: Execution row persisted; artifacts and duration_ms present

## Ledger persistence

- **Store**: SQLite (WAL mode), append-only
- **Location**: Demo uses a temp file; tests use `runtime/tests` temp dirs
- **Linkage**: `request_id`, `plan_hash`, `sandbox_id`, `ledger_row_id`
- **Schema**: `sandbox_ledger` table; payload JSON contains full `GovernedExecutionResult`-shaped summary

## Files
