# Branch Execution Notes — M3.11 Container Sandbox Runtime

## Objective

Implement a container-based sandbox runtime as a backend under the M3.10 driver abstraction. Stronger isolation; same governed semantics; fail-closed when backend unavailable.

## Backend choice and assumptions

- **Runtime**: Prefer `podman` then `docker` (shutil.which). Overridable via `ContainerSandboxDriver(runtime="/path/to/podman")`.
- **Image**: Default `python:3.12-slim`; overridable via constructor or `create_sandbox_driver("container", image="...")`.
- **Mount**: Host `working_dir` → container `/workspace`; `-w /workspace` for cwd.
- **Policy**: Same SandboxPolicy as local driver (command allowlist, working_dir); BLOCKED semantics preserved.

## DriverSpec

- **Not introduced.** Existing `run(command, working_dir, timeout_seconds, env, capture_artifacts)` is sufficient. Container-specific options (image, runtime, workspace_mount) live in the driver constructor. DriverSpec would not materially improve M3.11.

## Isolation guarantees achieved

- Workspace mounted as single read-write dir in container; exec form (no shell); timeout enforced; `--rm`; no fallback to host on failure.
- Resource limits (memory/cpus) not added; document as future extension.

## Fail-closed behavior

- No runtime found → `SandboxExecutionError` → executor returns EXECUTED (failed).
- Configured runtime path missing → `SandboxExecutionError`.
- Policy violation → `SandboxPolicyViolation` → BLOCKED (unchanged).
- Container run failure (e.g. image pull) → `SandboxExecutionError` or subprocess exception → EXECUTED (failed). No silent fallback to local process.

## Known limitations

- Container runtime (podman/docker) must be installed and in PATH for container backend to run; otherwise fail-closed.
- No memory/cpu limits in this milestone.
- Artifact scanning is host-side after run (same as local driver); container filesystem is ephemeral except mounted workspace.

## Merge risk

- **Low.** Additive only; default remains local process. Container is opt-in via `driver=ContainerSandboxDriver()` or `create_sandbox_driver("container")`. M3.10 seam unchanged; governance and ledger in executor unchanged.
