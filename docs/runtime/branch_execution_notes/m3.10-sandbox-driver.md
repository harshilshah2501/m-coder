# Branch Execution Notes — M3.10 Sandbox Driver Abstraction

## Objective

Introduce a pluggable sandbox driver abstraction beneath governed execution so that current local/process execution continues to work and a future container runtime (M3.11) can plug in cleanly. No governance bypass; no ledger contract regression.

## Boundaries

- **Primary**: `runtime/sandbox/**`, `runtime/tests/test_sandbox_*.py`, `runtime/tests/test_sandbox_demo_e2e.py`, `docs/runtime/**`, `docs/runtime/branch_execution_notes/**`
- **Minimal allowed**: `runtime/orchestrator/**`, `runtime/execute_service/**` only if strictly required for executor wiring (none needed for this milestone)
- **Do not touch**: `governance/**`, `ml/**`, `runtime/state/schemas/**`, `runtime/ide/schemas/**`, `jetbrains-plugin/**`, `docs/LIVE_ROADMAP_TRACKER.md`

## Design Summary

- **SandboxDriver** (Protocol): `run(...) -> SandboxResult`, `validate_only(...) -> tuple[bool, str]`. Drivers may raise `SandboxPolicyViolation`, `SandboxTimeout`, `SandboxExecutionError`.
- **LocalProcessSandboxDriver**: Wraps `SandboxRunner`; used by default when `SandboxExecutor(driver=None)`.
- **SandboxExecutor**: Holds `_driver: SandboxDriver`; all outcome construction, ledger append, and callbacks remain in the executor. No governance logic moved into the driver layer.

## Known Limitations

- No container driver in this branch (M3.11). Optional `DriverRequest` dataclass deferred until M3.11 if needed.

## Merge Risks

- **Low**. Additive seam only; default behavior unchanged. Existing callers of `SandboxExecutor()` get `LocalProcessSandboxDriver` implicitly. Custom drivers are opt-in via `SandboxExecutor(driver=...)`.

## Invariants Preserved

- Fail-closed behavior preserved.
- No bypass path introduced.
- Plan-Gate governance remains enforced.
- Append-only ledger behavior preserved.
- REFUSED / BLOCKED / EXECUTED semantics and `GovernedExecutionResult` contract unchanged.
