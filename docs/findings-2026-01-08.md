# Problem Analysis: "Create CorrectionProfileAPI.java" - Key Findings

**Date:** 2026-01-08  
**Analysis Focus:** Why models fail on simple instruction-following tasks  
**Impact:** Critical blocker for V16.1 → V17 improvement

---

## The Problem

**Test Case:**
```
Prompt: "Create CorrectionProfileAPI.java"
Expected: CorrectionProfileAPI class extending AbstractAPI
Actual (V16.2): AbstractCredentialUserProfile extending AbstractVerticle
Result: ❌ COMPLETE FAILURE
```

**Severity:** 🔴 CRITICAL - Model ignores instruction completely

---

## Root Cause Analysis

### 1. Training Data Format Mismatch

**What the model was trained on:**
```
100% SEARCH/REPLACE edits on existing files
Format: "Modify file X by replacing Y with Z"
```

**What we're testing with:**
```
"Create CorrectionProfileAPI.java"
Format: "Create new file with these requirements"
```

**The Gap:**
- ❌ No "Create new file" examples in training data
- ❌ No examples without full file content
- ❌ No examples with simple instructions
- ✅ 100% SEARCH/REPLACE edits on existing files

**Conclusion:** The model has NEVER seen this format during training!

## Hallucination Patterns Identified

### Pattern 1: File Hallucination (70% of failures)
- Model ignores task's expected files
- Generates changes for non-existent files
- Example: Asked for `CorrectionProfileAPI.java`, modified `DiscoveryManager.java`

### Pattern 2: Mode Collapse (30% of failures)
- Model defaults to same file repeatedly
- Example: Always outputs `Patch8014.java`
- Caused by over-representation in training data

### Pattern 3: Wrong Changes (20% of failures)
- Model identifies correct file but generates completely wrong modifications
- Example: Generic catch blocks instead of specific error handling

### Pattern 4: Generic Reasoning (100% of failures)
All `<thinking>` blocks are nearly identical:
```
**Problem**: [vague description]
**Plan**: 
1. Locate relevant code section
2. Apply necessary modifications
3. Ensure changes are minimal and focused
```

## Why RAG Alone Doesn't Fix This

**RAG System Status:**
- ✅ Correctly retrieves code patterns
- ✅ Provides accurate context
- ❌ Model ignores the context
- ❌ Model contradicts its own reasoning

**Example:**
```
RAG retrieves: UserProfile.java and CredentialProfile.java patterns
Model's thinking: "Follow these patterns"
Model's output: Completely different code
```

**Conclusion:** The problem is not retrieval, it's model behavior.

---

## Why SFT Alone Isn't Enough

**Current Pipeline (V16.1):**
- ✅ SFT training on code diffs
- ❌ No preference learning
- ❌ No instruction-following optimization
- ❌ No hallucination penalty

**What's Missing:**
- Model doesn't learn to prefer correct outputs over hallucinations
- Model doesn't learn to follow instructions over training patterns
- Model doesn't learn to avoid mode collapse

## The DPO Solution

**Why DPO Fixes This:**

1. **Preference Learning**: Model learns to prefer correct files over hallucinations
2. **Instruction Adherence**: Model learns to follow user instructions over training patterns
3. **Anti-Hallucination**: Model learns to avoid non-existent APIs and files
4. **Self-Consistency**: Model learns to match thinking with output

## Key Insights

### 1. Training Data Format Matters
- Models learn from examples, not instructions
- If training data is 100% SEARCH/REPLACE, model can't do CREATE
- Solution: Include diverse task types in training data

### 2. Explicit Anti-Hallucination Instructions Are Critical
**What Worked:**
```
## CRITICAL RULES (repeated 3 times in prompt):
- ONLY reference code from context above
- DO NOT invent class/method names
- If unsure, say "I don't have enough context"
```

**What Didn't Work:**
```
Please be accurate.  # Too vague!
```

### 3. Confidence Scoring Enables Better UX
- Models need explicit feedback on what's correct
- DPO provides this through preference pairs
- Enables better decision-making

### 4. Hybrid Retrieval (Vector + Graph) Helps But Isn't Sufficient
- Vector search finds similar code
- Graph search finds actual relationships
- But model still ignores context if not trained to use it
