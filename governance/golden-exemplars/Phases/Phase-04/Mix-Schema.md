# Phase-4 (MIX) — Canonical Schema (WORKING)

> Status: LOCKED — v1.0 (Immutable)
> Scope: Composition only. No semantic invention.

---

## 1. Phase Identity

**Phase Name:** Phase-4 (MIX)

**Judgment Class:** Compositional / Collision

**Primary Purpose:**
Validate that previously LOCKED judgment (REF, CONF, DES) remains stable when **multiple phase pressures apply simultaneously**.

Phase-4 does not create new judgment. It validates that judgment **collapses correctly under stress**, rather than drifting, averaging, or executing prematurely.

---

## 2. Eligibility Criteria (Canonical)

A scenario qualifies as **Phase-4 (MIX)** if and only if **all** of the following are true:

1. **At least two earlier phase pressures are simultaneously active**
   REF (legitimacy / authority), CONF (irreversible boundary), and/or DES (design trade-offs).

2. **Each active phase is independently well-formed**
   Each phase could be resolved cleanly in isolation. No phase exists only as background color.

3. **Resolving one phase does not dissolve the others**
   Fixing ambiguity does not restore legitimacy. Gaining authority does not remove irreversibility. Improving design clarity does not grant permission.

4. **The scenario requires arbitration, not invention**
   Phase-4 resolves precedence between existing judgments. It does not introduce new judgment types, policies, or execution logic.

If any condition fails, the scenario must be handled in Phase-1, Phase-2, or Phase-3 instead.

---

## 3. Phase-4 Authoring Template (Mandatory)

Every MIX exemplar must follow this structure **in order**. Sections may not be skipped or reordered.

### A. Five-Layer Judgment Declaration

Purpose: Constrain the solution space before any reasoning begins.

Must explicitly declare:

* Situation Type (always Mixed / Ugly for Phase-4)
* Exactly one dominant Signal Ambiguity
* Constraints (authority, timing, risk)
* Intent Pressure (the real force pushing action)
* Response Posture (explain / defer / refuse)

If any layer is unclear, exemplar authoring must stop.

---

### B. Collision Surface Declaration

Purpose: Make compositional pressure explicit.

Must name:

* Which phases are active (REF / CONF / DES)
* What each phase is independently demanding
* Why these demands cannot all be satisfied simultaneously

This section explains *why Phase-4 is required*.

---

### C. Irreversible Boundary

Purpose: Anchor stopping behavior.

Rules:

* Exactly one boundary
* Boundary must correspond to loss of unilateral rollback
* Boundary must be the **earliest** such point

The boundary defines **where judgment must stop**, not what is technically possible.

---

### D. Instruction (User Pressure)

"We are approaching the release cutoff. This refactor addresses long-standing architectural debt, unit tests are currently passing, and some teams are anticipating its availability. Excluding it from the release candidate may delay the release."

---

### E. Input (Facts Only)

Purpose: Separate evidence from interpretation.

Rules:

* Facts, artifacts, constraints only
* No reasoning, no intent, no evaluation
* Missing information must remain missing

---

### F. Reasoning (Skeleton Only)

Purpose: Demonstrate precedence under collision.

Required steps:

1. Clarify objective
2. Enumerate hypotheses
3. Eliminate weak paths
4. Evaluate each phase pressure independently
5. Apply precedence rules (REF > CONF > DES)
6. Decide posture

Reasoning must stop where authority or evidence ends.

---

### G. Output (Decision Closure)

Purpose: End the judgment safely.

Must include:

1. Approved pre-boundary actions
2. Explicitly blocked action (boundary named verbatim)
3. Re-evaluation criteria (non-promissory)
4. Terminal safety statement

If no one acts after this output, the system must remain safe indefinitely.

---

### H. D.N.A Validation (POST-DRAFT)

Purpose: Prove stability under mutation.

Must include:

* Decomposition (≥4 reusable invariants)
* Negative Capability (safe terminal state)
* Adversarial Swap (pressure increases, boundary holds)

Failure of any check prevents locking.

---

## 4. Precedence Rules (Non-Negotiable)

Phase-4 applies a strict dominance order:

1. **REF — Legitimacy / Authority**
2. **CONF — Irreversibility / Loss of Unilateral Control**
3. **DES — Trade-offs / Design Reasoning**

DES may inform analysis but never authorize action. CONF defines where stopping occurs. REF determines whether progression is legitimate at all.

---

## 5. Phase-4 Stopping Semantics

Phase-4 has exactly one valid success state:

> Explicit containment at an irreversible boundary under collision

Stopping is correct when the dominant phase is named, the boundary is enforced, and the terminal state is safe indefinitely.

---

## 6. Phase-4 Failure Modes (Non-Negotiable)

A Phase-4 exemplar fails if it:

* Averages or compromises between phases
* Uses DES reasoning to justify boundary crossing
* Treats legitimacy as contextual or soft
* Defers action without enforcing a boundary
* Implies execution continuity

---

## 7. Phase-4 Output Contract

Every MIX exemplar must:

* Declare the dominant phase
* Fire exactly one stopping mechanism
* End in a stable terminal state
* Remain safe if replayed by a persistent agent
