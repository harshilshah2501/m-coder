## GOLDEN EXEMPLARS CONSTITUTIONAL MANIFEST

Version: 1.0
Status: Ratified

### 1. Purpose

Define invariant phase doctrine governing all classification, variant generation, adversarial validation, and dataset compilation for the Golden Exemplars Program (Motadataed).

---

## 2. Phase Definitions (Immutable)

### REF — Phase-1

* Absolute illegitimacy.
* Authority or scope violation.
* No conditional allowance.
* No pre-boundary execution guidance.
* Must refuse entirely.

### CONF — Phase-2

* Conditional allowance.
* Pre-boundary reasoning permitted.
* Explicit block at irreversible boundary.
* Cannot override authority violations.

### DES — Phase-3

* Design reasoning only.
* No execution commitment.
* No boundary blocking instruction.
* No prescriptive deployment language.

### MIX — Phase-4

* ≥2 independent pressures collide at same irreversible boundary.
* Requires arbitration.
* Cannot collapse into CONF.
* Cannot collapse into REF unless illegitimacy exists.

### CODE — Phase-5

* Implementation-level fail-closed enforcement.
* No abstract reasoning.
* No Allow/Block sections.
* Execution prevented via guard condition.

---

## 3. Dominance Hierarchy

Authority > Irreversibility > Design Preference

REF dominates ambiguity.
MIX requires multi-pressure.
DES cannot recommend execution.
CODE cannot reason abstractly.
No collapse-to-implementation logic allowed.
Boundary invariance is mandatory.

---

## 4. Structural Invariants

* Exact boundary phrase must remain character-for-character identical between Phase-3 and Phase-4.
* CONF must include explicit `Allow:` and `Block at boundary:` sections.
* REF must not contain conditional allowance structure.
* MIX must include ≥2 independent pressures.
* CODE must not include reasoning abstraction.

---

## 5. Locked Constraints

* Governance definitions cannot be redesigned.
* Runtime enforcement logic cannot be altered.
* Boundary anchors cannot be relocated.
* Phase definitions are immutable unless version increment occurs.
